## Решения владельца (2026-11-16, закрытие блокеров)

- **Browser/perf/smoke:** остаётся отдельным шагом (не в этой среде агента); до закрытия browser-гейтов DoD по runtime формально открыт, но не блокирует CLI-разработку/эталоны/серии.
- **Perf/DoD:** по решению владельца (2026-11-16) perf-подобные гейты (picture-ground-geo budget, `reload-scene-budget`) **вынесены из DoD** — приоритет: хороший генератор уровней, играбельная runtime-корректность, а не бюджет кадра. Browser-run остаётся ручным шагом владельца.
- **Тестовые главы:** для быстрой итерации добавлена маленькая **смоук-глава `level-22`** (`512 м`, 4 чанка × 256 м, плита 512 м, 1 2×2 streaming, планка `--check` зелёная); целевой профиль тестов — по `level-22`, все уровни гоняются редко (только при большом изменении поведения контрактов).
- **Лог времени:** время выполнения этапов пишется в `.ai/state/citygen-run-log.md` (строки на шаг: дата, цель, команда/гейты, сколько заняло, результат).
- **Объём:** R0–R6 целиком (не сужение). Прогресс идёт по фазам; поведение и bump-артефакты фиксируются по R0.4.
- **Версионирование:** первое поведенческое изменение (layout/IR/report-affecting) → сознательный bump `generatorVersion` до **0.2.0**, пересоздание derived/baseline/эталонов по процедуре R0.4 (`--update`-поток), зафиксированный прогон гейтов.
- **GAP (приняты дефолты):** GAP-01 — сборный interchange из уровней/рамп без расширения DSL/схемы без ADR; GAP-06 — эпоха в `profileId/style`/`properties.era`, без поля в схеме; GAP-07 — различать типы районов через profile/overrides, enum не менять; GAP-11 — дефолт enterable только после проверки движка, безопасный дефолт `false`.
- **DoD-пилоты:** `level-17` (river_trade), `level-20` (hill_town), `level-21` (railway_industrial); фиксированные etalons/regression и зарегистрированные открытые главы.
- **≥100 seed:** прогнать 100 seed × 3 профиля, результат зафиксировать в репозитории (`.ai/state/citygen-seed-series/series-summary.json`).

## Процедура bump/versioning и регрессии (R0.4, формализовано: stated scope)

### Когда повышать `generatorVersion`
- **Повышать** при намеренном изменении раскладки/IR/отчёта, влияющем на воспроизводимый результат (геометрия, распределения, ID/порядок, диагностики/метрики, влияющие на report hash, и т.п.) для уровней с фиксированным seed+version.
- **Не повышать** для чисто нефункциональных правок, не меняющих детерминированный вывод/derived-артефакты.
- При bump: обновить `generator.generatorVersion` в затронутых исходниках/эталонных сценариях и зафиксировать причину в `.ai/state`/коммите.

### Регрессионный gate (текущее состояние, gv 0.69.0)
  - Синтетические эталоны 3×3: `.ai/state/citygen-etalons/` (`river_trade`,`hill_town`,`railway_industrial` × seeds `101,202,303`, `summary.json`, `generatorVersion=0.69.0`) с hash/summary/rules/metrics.
  - Pilot baselines: `.ai/state/citygen-baselines/level-16..22.citygen-baseline.json` (source pilots L16–L22).
  - Проверка (локальная prep/CI): `node tools/citygen-etalon-check.mjs` — сравнивает etalon snapshots (hash/summary/rules/metrics) и baselines (hash/summary/rules). CI gate: `.github/workflows/ci.yml` job `node-etalon` (`node / etalon regression`, R0.4/R6).
  - При output/derived изменениях дополнительно: `node tools/build-level.mjs <level.json> [--check]` (0 warnings/детерминизм), `node tools/check-levels.mjs <scope>`, `node --test tools/citygen.test.mjs`, browser/perf/seed-series гейты по scope (GitHub CI — источник истины).

### Контролируемое обновление при намеренном изменении поведения
1. Внести изменение генератора/правил.
2. Пересобрать затронутые derived-артефакты пилотов/уровней: `node tools/build-level.mjs src/levels/level-XX.json ...` (и `--check` для паритета).
3. Обновить pilot baselines: `node tools/citygen-baseline.mjs --out .ai/state/citygen-baselines src/levels/level-16.json src/levels/level-17.json src/levels/level-18.json src/levels/level-19.json` (или нужный scope).
4. Обновить synthetic etalons: `node tools/citygen-etalon-check.mjs --update` (обновляет несовпавшие etalon/*.json и `summary.json`). Для смены версии synthetic-сценариев: `node tools/citygen-etalon-check.mjs --update --generatorVersion <v>`.
5. Прогнать scoped-гейты: `node tools/build-level.mjs --check ...`, `node tools/check-levels.mjs ...`, `node --test tools/citygen.test.mjs`, `node tools/citygen-etalon-check.mjs`, релевантные browser/perf-гейты по scope.
6. Зафиксировать изменения derived/снапшотов/версий и причину в `.ai/state` и коммите.

### Политика воспроизводимых source/profile pilots (R0.4, уточнение)
- Source/profile pilots (`src/levels/level-17.json`, `src/levels/level-20.json`, `src/levels/level-21.json`) фиксируют воспроизводимость через: `generator.seed`, `generator.profile`/`profileDriven` (или эквивалентный профиль), `generator.generatorVersion` (`DEFAULT_GENERATOR_VERSION`/явное значение), детерминированные параметры.
- При любом намеренном изменении поведения (layout/IR/report/derived): пересобрать `src/levels/level-NN/*`, прогнать `node tools/build-level.mjs src/levels/level-NN.json --check`, `node tools/check-levels.mjs <scope>` (и/или registry-scope), `node --test tools/citygen.test.mjs`, `node tools/citygen-etalon-check.mjs`, обновить `.ai/state/citygen-baselines/level-NN.citygen-baseline.json` и при необходимости synthetic etalons; зафиксировать причину в `.ai/state`.
- Bump `generator.generatorVersion`: при изменениях, ломающих воспроизводимость относительно зафиксированной версии/эталонов; обновить версию в затронутых source pilots/сценариях, пересобрать derived, обновить snapshots/эталоны контролируемо (`--update`, при synthetic-bump `--generatorVersion <v>`), прогнать гейты.
- Регистрация в `src/levels/index.js` (browser/perf/regression scope) — только после подтверждённых browser/perf/smoke-gates по затронутым главам/режимам; до этого пилоты остаются воспроизводимыми source+derived+baseline артефактами вне runtime registry.
